# PortSwitch MCP

MCP server that helps AI coding agents (Claude Code) resolve port conflicts between
local dev environments without destroying data.

## Requirements

- macOS or Linux
- [Docker](https://docs.docker.com/get-docker/) with Docker Compose v2 (`docker compose`)
- **[uv](https://docs.astral.sh/uv/getting-started/installation/)**, the Python package manager

## Setup (once per machine)

In the repo root run:

```bash
uv sync
```

This installs the right Python version and the exact dependency versions from `uv.lock`.

## Try the server by hand

```bash
uv run mcp dev src/portswitch/server.py
```

Opens the MCP Inspector in your browser, where you can call the tools without any AI.

To also see the internal helper functions as tools while debugging, start the debug
entry point instead:

```bash
uv run mcp dev src/portswitch/debug_server.py
```

Agents never see these helpers: `.mcp.json` only registers `server.py`.

## Use it from Claude Code

The server is registered in `.mcp.json`, so it loads automatically.
Start `claude` in the repo root, approve the `portswitch` server when asked,
then run `/mcp` to check it is connected.

To use it in another project folder, register it there with the absolute path to this repo:

```bash
claude mcp add --transport stdio portswitch -- uv run --directory /ABSOLUTE/PATH/TO/portswitch-mcp portswitch
```

### Always ask before `stop_project`

`stop_project` is the only tool that changes anything, so Claude Code should always ask you first,
even in auto mode. Add this to `~/.claude/settings.json` (applies to every project):

```json
{
  "permissions": {
    "ask": ["mcp__portswitch__stop_project"]
  }
}
```

## Project layout

```
.mcp.json                 # registers the server for Claude Code (shared via git)
pyproject.toml            # project metadata + dependencies
uv.lock                   # exact versions, generated by `uv sync` (commit it)
.python-version           # Python version uv uses
src/portswitch/server.py  # the MCP server and its tools
src/portswitch/debug_server.py  # same server + helpers + ping as tools, for the Inspector only
```

## Tools and sample responses

| Tool | What it does | Changes anything? |
| --- | --- | --- |
| `check_conflicts(path)` | Which ports of the project in `path` are taken, and by which project folder | No |
| `suggest_free_port(port)` | Nearest free host port at or above `port` | No |
| `stop_project(path)` | `docker stop` on every container of the compose project started from `path`; data is kept | Yes, asks first |

The server also sends Claude Code short instructions: check first, explain, then either stop
the other project after the user agrees or remap the current project's own port.
It never offers `down`, `down -v`, `docker rm` or `docker volume rm`.

### `check_conflicts(path)`

Project `new-project` runs PostgreSQL on port `5432`. Its `docker compose up` fails because
`old-project` already holds that port:

```json
{
  "project": "/Users/josef/tools/new-project",
  "conflicts": [
    {
      "port": 5432,
      "container": "old-project-db-1",
      "compose_project": "old-project",
      "project_folder": "/Users/josef/tools/old-project"
    }
  ]
}
```

For `old-project` itself there is no conflict, because a project does not conflict with itself:

```json
{
  "project": "/Users/josef/tools/old-project",
  "conflicts": []
}
```

### `suggest_free_port(port)`

If port `5432` is taken, the tool suggests the nearest free port:

```json
{
  "requested": 5432,
  "free_port": 5433
}
```

If port `5432` is free, `free_port` equals the requested port:

```json
{
  "requested": 5432,
  "free_port": 5432
}
```

### `stop_project(path)`

`path` is the `project_folder` from `check_conflicts`. Containers are stopped, not removed,
so the database keeps its data:

```json
{
  "project_folder": "/Users/josef/tools/old-project",
  "compose_project": "old-project",
  "stopped": ["old-project-db-1"],
  "data_kept": true,
  "resume_with": "cd /Users/josef/tools/old-project && docker compose start"
}
```

If no running compose project was started from that folder, nothing is stopped:

```json
{
  "project_folder": "/Users/someone/else",
  "stopped": [],
  "note": "No running docker compose project was started from this folder. Nothing was stopped."
}
```

### Errors

When Docker is not running or the folder has no compose file, tools return an `error` field
instead of crashing, so the agent can explain the problem:

```json
{
  "project": "/Users/josef/tools/empty-folder",
  "error": "`docker compose config --format json` failed: no configuration file provided: not found"
}
```
